- 暂时保持全部 7 个右臂关节：肩 `(0.2,-0.1,0)`、肘 pitch `-π/2`、末端三关节 `0`；其余 22 维学习平衡。仿真、想象、历史、replay、评估共享动作覆盖规则，基座自由浮动。
- 40 秒常值参考及接触标签位于 `data/tienkung3_29dof/standing_aiming/`；每回合从第一帧开始训练 30 秒。世界原点、脚位和朝向参考固定。
- 奖励使用 SuperMimic 跟踪与接触项，另加 `K(e,s)=1/(1+(e/s)^2)`：骨盆位置 `(权重2,尺度0.10m)`、双脚位置平均 `(2,0.05m)`、骨盆水平速度 `(1,0.10m/s)`、双脚水平速度平均 `(0.5,0.10m/s)`、朝向 `(0.5,5°)`。这些项不受原 PaperReward 静止掩码影响，仿真与想象使用同一奖励。
- 首轮 512 环境、WM/policy batch 256、hist 10、horizon 32、buffer 1000、lr `1e-4`、余弦周期 10000；前 500 次只更新 WM，最多 10000 次。物理、初始化、观测和指令噪声关闭；身体动作探索噪声从 0.05 在前 3000 次线性降至零。
- 每 500 次评估连续 30 秒并保存完整检查点。达到验收后重新加载复验，通过即停止；未达标保留最佳结果并如实记录。

当前接口实现位于 `supermimic/acp/standing.py`、`standing_eval.py` 及 Stage1 训练入口。生成参考使用 `python -m tools.generate_standing_motion --robot tienkung3_29dof --pose standing_aiming --seconds 40 --out data/tienkung3_29dof/standing_aiming/motions`；标签仍由 `supermimic.acp.make_labels` 生成。

正式运行命令（已经完成的目录不要直接重复启动；新实验使用新的 `--log_dir`）：

```bash
conda activate acp_supermimic
OMP_NUM_THREADS=8 MKL_NUM_THREADS=8 python -m supermimic.acp.train_stage1 \
  --task standing_aiming --robot tienkung3_29dof \
  --finetune logs/imported/5090/stage1_fixed8_from100k_20261111/ckpt_100500.pt \
  --motion_dir data/tienkung3_29dof/standing_aiming/motions \
  --contacts_dir data/tienkung3_29dof/standing_aiming/contacts \
  --num_envs 512 --wm_batch 256 --pi_batch 256 --buffer_steps 1000 \
  --hist 10 --horizon 32 --iterations 10000 --wm_only_iters 500 --wm_batches 10 \
  --lr 1e-4 --lr_decay_iters 10000 --action_noise .05 \
  --ckpt_every 500 --log_every 25 --save_full_checkpoints \
  --log_dir logs/tienkung3_29dof/standing_aiming_from100500_20261111/train
```

需续训时保留该运行的配置，将 `--finetune` 换成 `--resume <last.pt>`；迭代数表示该运行的总迭代上限，不是新增次数。

## 1. 任务与首版默认方案

用户已确认：右肩固定、肘部保持弯曲约 90°，用末端三个自由度指向世界中的固定目标点。首版从持臂姿态开始，先完成一个固定目标，再增加小范围随机目标。

首版沿用当前 MuJoCo/mjlab、PD、FK 与 SuperMimic 基础，不同时迁移学习算法。使用已经验收的持臂站立权重初始化同一个 actor，加入瞄准指令并启用末端三维输出。IK 仅可用于训练辅助或几何检查；最终推理不需要 IK 解，也不使用 `q_IK + Δq_policy`。

肩部固定指关节相对躯干保持目标角度；机器人仍是自由浮动系统，肩肘由 PD 保持，不通过焊接关节改变模型。身体轻微晃动时，末端根据实际姿态继续补偿。

### 1.1 关节分工

| 控制组 | 关节 | 数量 |
|---|---|---:|
| 同一个 policy 的身体输出 | 双腿 12、腰部 3、左臂 7 | 22 |
| 固定持臂姿态 | `shoulder_pitch_r_joint`、`shoulder_roll_r_joint`、`shoulder_yaw_r_joint`、`elbow_pitch_r_joint` | 4 |
| 同一个 policy 的末端输出 | `elbow_yaw_r_joint`、`wrist_pitch_r_joint`、`wrist_roll_r_joint` | 3 |

**2026-11-11 用户观看双视角关节预览后确认采用上述定义。** 末端三自由度明确为“前臂旋转＋两个腕关节”：`elbow_yaw_r_joint`、`wrist_pitch_r_joint`、`wrist_roll_r_joint`。固定组为右肩三关节和肘部屈伸，共四个；模型没有第三个独立命名的腕关节。后续按此分组实现，无需再次确认映射。

首版沿用此次确认预览中的持臂姿态：右肩 pitch／roll／yaw 为 `(0.20, -0.10, 0.00) rad`（约 `11.46°、−5.73°、0°`），肘部 pitch 为 `-π/2`（−90°），末端三关节初始均为 0。原模型默认肘角为 `-0.50 rad`，实现时需要显式覆盖。

固定版本 URDF 的肘部 pitch 限位为 −146°～11°，因此不能直接写成 `+π/2`。末端前臂旋转范围为 ±163°，两个腕关节各为 ±76°；这些是单关节行程，不等于整体可瞄准角度。来源见 [资产列表](asset_list.md)。

### 1.2 世界目标与指向轴

在 `right_tcp_link` 上定义指向原点和局部单位轴 `u_H`。首版沿用此次预览红箭头的局部 `-Z`，即 `u_H = (0, 0, -1)`；后续若装工具，再采用工具安装偏移。当前持臂姿态下，其世界方向约为 `(0.98009, -0.01600, -0.19791)`，朝前并向下约 11.4°，不是水平朝前。

对固定世界目标 `p_target_w`，每个控制步用实际手部位置 `p_hand_w` 和姿态 `R_hand_w` 计算：

```text
direction_actual_w = R_hand_w @ u_H
direction_target_w = normalize(p_target_w - p_hand_w)
```

指向任务只要求两条方向一致，不要求手部移动到目标点，也不额外强制完整手掌朝向。三个关节的多余自由度用于保持自然姿态、减少动作和保留限位余量。

首个目标放在初始手部指向前方约 3 m。随机目标的初始建议范围是该方向附近水平 ±15°、垂直 ±10°、距离保持 3 m；这些是首版开发默认值，M0 若发现局部不可达就缩小范围。每回合只在开始时采样一次并存为世界坐标，不能每步跟随机器人重新生成目标。

## 2. 最小开发路径

### M0：接好单 policy 的目标输入与末端输出

- **当前状态**：模型与运动学预览已完成，关节定义已获用户确认；目标 IK 与控制接入尚未完成。
- **输入**：已准备的机器人模型、现有配置、FK 和上述持臂姿态。
- **剩余工作**：保留 29 维输出接口，仅覆盖肩肘四维，释放末端三维；增加独立瞄准指令。三个新启用的输出初始化为当前中立目标，不直接启用原本被屏蔽的旧输出。用 FK 或离线 IK 检查少量近邻目标的可达性。
- **交付**：25 维有效动作、4 维固定目标的统一动作接口，指向误差与目标采样逻辑。
- **完成条件**：末端三维真正影响仿真并接收梯度；方向正反正确，目标在已检查的范围内。固定基座仅用于几何检查。
- **依赖**：本地模型资产可用。完成后直接进入自由站立，不另做长期固定基座训练。

### M1：固定持臂姿态下站立并对准单个目标

- **输入**：M0 配置、常值站立参考、身体策略初始化。
- **工作**：完整自由浮动模型由同一个 actor 控制身体 22 维和末端 3 维，肩肘四维保持固定；加入指向奖励，去除与末端运动冲突的旧参考跟踪。先学习当前方向附近的少量固定目标，再扩大范围。
- **初始化**：使用当前主线微调得到并验收的持臂原地站立策略。
- **交付**：能够独立完成站立和定点瞄准的单 actor 检查点、配置和录像；验收时关闭 IK／示教辅助。
- **完成条件**：机器人能够自由站立并保持指向，记录持续时间和角误差；初始效果目标见 [验证说明](validation.md)。
- **依赖**：M0 完成。用于 30 秒评估的常值参考需要覆盖该时长，避免被原有短片段结束条件提前截断。

### M2：小范围随机目标与保持

- **输入**：M1 控制器、M0 确定的小范围目标分布。
- **工作**：不同回合使用不同固定世界目标；运行稳定后，再加入回合内目标切换，并限制关节目标变化速度以减少突变。
- **学习路径**：继续训练同一个 actor，逐步扩大可达目标分布并加入目标切换。可选离线 IK 目标仅提供辅助监督，退火后以实际指向和站立奖励联合优化。
- **交付**：随机目标配置、一个可部署 actor、角误差摘要和代表性录像。
- **完成条件**：多个目标能对准并保持；目标切换后能重新稳定。首版无需多算法、多种子对照或完整外力扰动套件。
- **依赖**：M1 完成。

## 3. 必要的控制与训练接入

### 3.1 动作合成

当前动作接口为 `q_target = q_default + joint_offset + action_scale * a`，天工配置中 `action_scale=0.25`；策略控制频率 50 Hz，物理频率 200 Hz。首版保持这些约定。

保留原策略的 29 维输出，实际使用身体 22 维和末端 3 维，仅覆盖右肩肘四维。末端动作表示相对固定中立姿态的关节目标偏移，不以实时 IK 解为基准。合成后使用现有归一化动作约定，避免弧度和归一化动作混用或重复添加关节偏置。

仿真执行、`a_prev`、动作平滑奖励以及 replay 保存的动作，都采用最后实际下发的 29 维结果。各组按关节名建立索引，每个关节只有一个控制来源。

### 3.2 观测与任务输入

保留现有全身关节位置、速度、身体角速度、重力方向和历史动作。向同一个 actor 的 command 增加机体坐标系中的目标方向及当前 TCP 指向；方向按实际 TCP 位置与固定世界目标重新计算。原有站立位置指令保留，不替换为瞄准目标。

实际肩肘角度用于 FK，不能用固定指令值代替实际姿态。部署时只需状态／目标坐标变换、单 actor、固定肩肘覆盖及 PD，不依赖训练时的 critic、世界模型或 IK。

首版仿真可使用真实状态计算目标相对量；实机目标定位与状态估计作为后续工作。目标点是独立的瞄准指令，不复用现有移动目的地或右手接触目标的含义。

### 3.3 奖励调整

| 部分 | 最小调整 |
|---|---|
| 站立身体 | 保留腿部、躯干和足部约束；记录站立漂移、滑脚和跌倒 |
| 右肩与肘部 | 采用新的固定持臂角度，替换原动作中的角度参考 |
| 末端三关节 | 不再追踪原动作的关节轨迹；以方向误差和适度动作平滑为主 |
| 右手、右肘身体位姿 | 去掉与指向任务冲突的旧参考位置／姿态跟踪项，继续保留必要的限位和碰撞约束 |

指向奖励可使用 `-(1 - dot(direction_actual_w, direction_target_w))`，评估再转换为角度。它与站立、脚位、平滑及限位项组成同一个 actor 的总奖励，不为每个关节建立独立 policy。不能对点积取绝对值或平方后作为唯一对准奖励，否则可能把反向指向当作成功。

“保持”意味着持续小指向误差，不是关节始终静止。身体晃动时需要末端运动补偿，因此平滑惩罚不应压过指向需求。首版先用简单连续奖励，不设计复杂的奖励交接课程。

### 3.4 SuperMimic 一致性

这一部分需要随最小功能一起接通：真实仿真和世界模型想象必须执行同一套 25 维 actor 动作＋4 维固定覆盖。每个想象步根据预测手部状态重新计算目标方向，世界目标点本身保持不变。

replay 需保存瞄准目标，以及重建指令所必需的模式／平滑状态；采样起点时也要取出这些字段，不能只扩展存储。Actor 和 critic 都要获得对应任务条件。世界模型未必需要瞄准语义，但必须看到真实合成动作，并用新持臂姿态的数据更新。

增加输入维度或改变奖励后使用显式权重迁移，保留已有输入权重及归一化统计，新增输入列初始化为零并单独处理尺度，重建 critic。新增任务不直接使用旧 `--resume`。新采集的末端运动数据用于适配世界模型，然后小学习率联合训练 actor；初期可用冻结站立策略对身体 22 维提供动作蒸馏约束，但它不参与最终部署。共享网络中仅冻结身体输出层不足以保证身体行为不变，仍须检查完整站立结果。

## 4. 后续路线

站立功能可用后，先加入低速平地行走，再加入不需要右手或右肘支撑的低台阶。每次先确认固定持臂姿态下的移动能力，再接入相同的世界目标指向模块。

固定肩肘意味着可指向范围有限；路线经过目标之后，目标可能变得不可达。后续行走任务需要考虑这一点，首版站立无需提前解决任意路线与任意目标的组合。

从下垂手臂进入肘部 90° 的抬手动作另作姿态过渡。完整扰动测试、实机部署、复杂攀爬、PPO 对照和多策略蒸馏均留到实际需要时展开。
