# 单卡与双卡性能实测

测试日期：2026-11-08。原始数据见 [results.json](results.json)，精确参数见 [commands.json](commands.json)。环境与 512 环境显存检查见 [测试档案首页](README.md)。

每个阶段在相同数据、全局配置、精度和初始检查点下，顺序运行双卡与单卡作业。全局环境数 64，world-model/policy/planner batch 均为 64，horizon 8，world-model 窗口 2，每轮 1 次 world-model 更新、1×2 次 critic 更新；planner 子批次数 2、最少样本 16。world-model、policy、critic 的 MLP 使用 BF16；planner 训练使用 FP32，允许 TF32。每个作业运行 80 轮，前 10 次有效训练循环用于预热，随后连续测量 50 次。

Stage 1、Stage 2 的 `reward_chunk_size=0`，Stage 3 的单卡和双卡均为 `64`。离线采样策略的精度继承同一 tracker 检查点；planner 优化沿用 eager FP32，在线生成 planner 目标时使用 FP16 推理。单卡使用物理 GPU 1，双卡使用 GPU 0、1。计时包含正常采样、仿真、训练、周期日志和验证；初始化、replay 预填充及初始编译不在窗口内。每个阶段仅采集一次 50 轮窗口，未估计跨运行方差。

## 结果适用范围

四阶段均完成真实仿真、反向传播和实际优化器更新；Stage 1/2/3 覆盖编译反向，离线 planner 沿用 eager 训练。双卡检查点的模型、优化器和共享课程/调度状态哈希一致，所有最终性能作业的非有限梯度跳过次数为 0。

上述加速比来自短片段数值测试和小批量配置。512 环境档案是另外一次 3 轮资源检查，不能用本表直接预测其训练速度。独立的合成常值姿态、测试学习率和放宽的 planner 阈值用于覆盖更新路径，不代表真实运动数据上的训练质量或收敛速度。

未启动长期训练。后续正式训练可从首页给出的 512/256/256/512 全局规模和奖励分块 64 起步，使用实际动作数据重新检查显存与吞吐。
