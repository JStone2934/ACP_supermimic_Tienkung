## 评估协议对比（关键）

Stage1 与 Stage2 的评估协议不同，直接比较会误导。这里补跑了同协议对照：

| 运行 | 终止窗口 | 动作噪声 | norm_return | 失败 / 2960 |
|---|---|---|---|---|
| Stage1（正式） | 严格 0 s | 无 | **0.527** | 837（28.3%） |
| Stage1（对照） | ±2 s | 0.1 | 0.514 | 807（27.3%） |
| Stage2（正式） | ±2 s | 0.1 | 0.429 | 801（27.1%） |
| Stage2（严格对照） | 严格 0 s | 无 | 0.374 | 1545（52.2%） |

在**相同协议**（±2 s + 动作噪声）下，Stage1 与 Stage2 的失败数几乎相同（807 vs 801），但 Stage2 的
norm_return 明显更低（0.429 vs 0.514）——这与上游 README 的解释一致：规划器让机器人按自己的节奏走，
回报是按参考时间计的，所以偏低。严格窗口下 Stage2 失败率翻倍，主要是“晚于参考”而非跌倒。

**高攀爬的 56.2% 不是真实进步**：存活片段的 root RMSE 中位数约 **1.95 m**，说明只是靠 ±2 s 窗口“拖着没被终止”，
并没有跟上参考；严格窗口下仍是 100% 失败。低攀爬自始至终 100% 失败。

## 接触落点：Stage2 的主要收益

| 指标（脚，左/右） | Stage1 严格 | Stage2 ±2 s+噪声 |
|---|---|---|
| 落点误差中位数 | 18.9 / 22.9 cm | **6.2 / 6.9 cm** |
| 误差 ≤0.1 m 占比 | 19.7% / 13.0% | **67.4% / 65.8%** |
| precision / recall | 0.856 / 0.968 | 0.696 / 0.970 |

规划器目标被跟踪器执行得更准（约 3 倍改善），代价是接触 precision 下降、整体参考跟踪变差。

## 规划器在线指标

| 检查点 | 脚 F1（左/右） | 膝 F1（左/右） |
|---|---|---|
| 离线 20k | 0.83 / 0.81 | 0.32 / 0.25 |
| 联合 40k | 0.628 / 0.585 | 0.281 / 0.314 |

联合训练后规划器的 occupancy F1 反而下降，是本次 Stage2 跟踪退化的可能原因之一；膝、手的正例仍偏少
（手在评估中有 619/926 个 onset，膝 precision 仅约 0.01）。

## 结论

1. Stage2 流程完整跑通，接触落点显著改善（脚 6–7 cm），说明 planner→tracker 的接触目标通路有效。
2. 但整体参考跟踪与 step/locomotion 成功率下降：同协议下失败数相近、回报更低，严格协议下失败翻倍。
   **不能宣称 Stage2 优于 Stage1**；需要参考跟踪时 Stage1 `last.pt` 仍是更好的选择。
3. 攀爬仍未解决：low-climb 100% 失败，high-climb 的表观改善是终止窗口放宽的假象。
4. 规划器在线 F1 下降与膝/手标签不足，是需要优先排查的方向。

## 后续建议

- 先补攀爬：用 Stage1 断点做攀爬专项 fine-tune 或检查攀爬动作/地形可行性，再谈 Stage2 攀爬规划。
- 规划器：联合训练阶段降低 planner 学习率或减少更新次数，避免离线 F1 退化；检查膝部标签覆盖与扫描可达性。
- 评估：固定同时报告“严格窗口”和“±2 s 窗口”两套数字；本文件的两套对照应作为后续基线。
